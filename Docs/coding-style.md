# Coding Style

Правила оформления кода для RTSEngine.

## Именование

- Типы, структуры, классы и функции верхнего уровня оформляются в `PascalCase`.
- Переменные и параметры функций оформляются в `camelCase`.
- Константы обозначаются через `constexpr`, а не через `#define`.

## Организация файлов

- Один логический тип или модуль должен иметь свой заголовок и реализацию, если это оправдано.
- Заголовки должны включать только необходимые зависимости.
- Где возможно, лучше использовать предварительные объявления.

## Стиль кода

- Избегать `using namespace std`.
- Предпочитать простую и читаемую структуру функций.
- Не смешивать в одном файле отрисовку, вычисления и бизнес-логику без необходимости.
- Писать комментарии только там, где они помогают понять назначение модуля или сложную логику.

## Комментарии

- Шапка файла должна кратко объяснять назначение модуля.
- Комментарии внутри функций нужны только для нетривиальных участков.
- Не дублировать очевидный код комментариями.
